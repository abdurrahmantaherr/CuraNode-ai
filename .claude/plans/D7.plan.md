# PLAN — D7: Doctor Multi-Hospital Schedule Management

Source of truth: `.claude/specs/D7-multi-hospital-schedule.md` (the "spec", v8).
Where it disagrees with `docs/TDD.md`, the spec wins; the live shared schema wins
over both. Branch: `feature/D7-multi-hospital-schedule`.

## 1. Summary

Doctors, verified or pending, manage recurring weekly slots per clinic
(affiliation) and per-date exceptions:
- **time off**: a whole slot, or a window inside it;
- **extra hours**: anchored to a slot, with an optional cap of their own.

The design maps onto the shared `doctor_schedule`/`schedule_exception` tables
(no new tables). It guarantees no two effective windows overlap at any clinic,
and exposes one read path, `get_effective_availability`. Before any of that,
T0 repairs the Alembic chain: the shared DB is at `e3a52c8d7f14`, a revision
unknown to this repo.

## 8. Scaffolding notes

- SQLite can't `ADD CONSTRAINT`, so the D7 migration uses
  `op.batch_alter_table` for both tables. On Postgres it emits plain
  `ALTER TABLE … ADD CONSTRAINT`. Check this in the offline SQL.
- A `time` column on SQLite round-trips as a string, so compare `datetime.time`
  objects in Python, not SQL strings.
- Assert the lock on compiled SQL:
  `str(stmt.compile(dialect=postgresql.dialect()))` contains `FOR UPDATE`.
- Freeze "today" with `monkeypatch.setattr(dbtypes, "today_pk", …)`, which is
  how the code reads it (`types.today_pk()`).
- `appointment` isn't mapped. R10 uses a `sa.table("appointment", …)`
  lightweight construct for the count. Tests create that table in SQLite for
  the R10 cases only.
- `ScheduleConflict.details` hold scalars only, so `message_params`
  substitutes them. Put the weekday number in `day` and localise it in the
  handler before rendering.
